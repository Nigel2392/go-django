# Translations

The `translations` app (`github.com/Nigel2392/go-django/contrib/translations`) provides YAML-backed translation loading, locale detection middleware, pluralization rules, a JavaScript translation catalog endpoint (`/i18n/translations.js`), and the `make-translations` CLI extractor.

For core `src/core/trans` translation helpers (`trans.T`, `trans.S`, `trans.P`, `trans.SP`, and template functions), see [Core Translations](../translations.md).

## Installation and Configuration

Add `translations.NewAppConfig` to `django.Apps(...)` and configure the `APPVAR_TRANSLATIONS_*` settings you need:

```go
package main

import (
	"github.com/Nigel2392/go-django/contrib/translations"
	django "github.com/Nigel2392/go-django/src"
	"golang.org/x/text/language"
)

func main() {
	app := django.App(
		django.Configure(map[string]any{
			django.APPVAR_ALLOWED_HOSTS:                []string{"*"},
			django.APPVAR_TRANSLATIONS_DEFAULT_LOCALE:  language.English,
			translations.APPVAR_TRANSLATIONS_DIR:       []string{"."},
			translations.APPVAR_TRANSLATIONS_LOCALES:   []string{"en", "nl", "de"},
			translations.APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE: []language.Tag{
				language.English,
				language.Dutch,
				language.German,
			},
		}),
		django.Apps(
			translations.NewAppConfig,
			// ... your other apps
		),
	)

	if err := app.Serve(); err != nil {
		panic(err)
	}
}
```

### Settings Constants

```go
const (
	APPVAR_TRANSLATIONS_DIR             = "APPVAR_TRANSLATIONS_DIR"            // []string (note: read as []string in make-translations)
	APPVAR_TRANSLATIONS_LOCALES         = "APPVAR_TRANSLATIONS_LOCALES"        // []string
	APPVAR_TRANSLATIONS_PACKAGES        = "APPVAR_TRANSLATIONS_PACKAGES"       // []string
	APPVAR_TRANSLATIONS_EXTENSIONS      = "APPVAR_TRANSLATIONS_EXTENSIONS"     // []string
	APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE = "APPVAR_TRANSLATION_ACCEPT_LANGUAGE" // []language.Tag
)
```

- `APPVAR_TRANSLATIONS_DIR`: `[]string` of directories searched by `make-translations` (defaults to the current working directory if unset).
- `APPVAR_TRANSLATIONS_LOCALES`: `[]string` of locale codes generated by `make-translations`.
- `APPVAR_TRANSLATIONS_PACKAGES`: `[]string` of extra Go package import aliases recognized by the Go source finder alongside `github.com/Nigel2392/go-django/src/core/trans`.
- `APPVAR_TRANSLATIONS_EXTENSIONS`: `[]string` of template file extensions (without leading dot) scanned by the template finder. Defaults to `[]string{"tmpl", "html", "txt"}`.
- `APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE`: `[]language.Tag` passed to `language.NewMatcher` inside `TranslatorMiddleware`. Note the underlying string key is `"APPVAR_TRANSLATION_ACCEPT_LANGUAGE"` (singular `TRANSLATION`), and it defaults to `[]language.Tag{language.English, language.Dutch}`.

See [Configuring](../configuring.md) for setting `django.APPVAR_TRANSLATIONS_DEFAULT_LOCALE` and other global variables.

## Loading `translations.yml` and Custom Filesystems

During `Init`, `translations.NewAppConfig()` loads and merges `translations.yml` from up to three sources in order:

1. The embedded `translations.yml` shipped with `contrib/translations`.
2. `./translations.yml` in the application's working directory (`os.Getwd()`), if present.
3. Any `translations.yml` present inside filesystems returned by `goldcrest` callbacks registered on `translations.TranslationFilesystemHookName`:

```go
type (
	TranslationFinderHook     func(settings django.Settings) []Finder
	TranslationFilesystemHook func(settings django.Settings) []fs.FS
)

const (
	TranslationFinderHookName     = "translations.finder.register"
	TranslationFilesystemHookName = "translations.filesystem.register"
)
```

During `Ready`, `translations` assigns `&Translator{...}` to `trans.DefaultBackend`, enabling `Translate`, `Translatef`, `Pluralize`, `Pluralizef`, and `TimeFormat` across Go code and templates. You can also query whether a non-empty translation exists using `translations.Translate(v string, locales ...language.Tag) (string, bool)`.

## Locale Middleware (`TranslatorMiddleware`)

`translations.NewAppConfig()` registers `TranslatorMiddleware()` on the root router (`m.Use(TranslatorMiddleware())`):

- Skips static asset requests (`django.IsStaticRouteRequest(req)`).
- Reads the `"lang"` cookie (`req.Cookie("lang")`) and the `Accept-Language` HTTP header.
- Matches them against the `APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE` matcher (`language.MatchStrings`).
- Attaches the resolved `language.Tag` to the request context via `trans.ContextWithLocale`.

## JavaScript Catalog (`/i18n/translations.js`)

`translations` mounts a `GET` route named `"translations.js"` at `/i18n/translations.js` and automatically registers it with `admin.RegisterGlobalMedia` so the [Admin App](./admin/app.md) loads it on every admin page.

You can also include it in your own frontend templates:

```html
<script src="{{ url "translations.js" }}"></script>
```

The endpoint renders a script (`application/javascript; charset=utf-8`) for the request's active locale and initializes `window.i18n`:

```javascript
window.i18n.gettext("Save changes");
window.i18n.gettext("Hello, %s!", username);

window.i18n.ngettext("1 item", "%d items", count, count);
window.i18n.pluralidx(count);

// Raw catalog and locale header metadata:
console.log(window.i18n.translations, window.i18n.header);
```

Internally, `/i18n/translations.js` bundles a lightweight `window.sprintf` (`%s`, `%q`, `%d`, `%f`, `%v`, `%#v`, `%T`, `%%`) and an FNV-1a 32-bit UTF-8 hash matching the Go backend so plural lookups work identically on server and client.

## Extracting Strings with `make-translations`

`translations` registers the `make-translations` CLI command to scan your codebase and update `./translations.yml`:

```bash
go run ./... make-translations -dir . -locales en -locales nl -e vendor
```

Flags (using repeatable `flags.List` arguments):

- `-dir`: Directory to scan (repeatable; defaults to `APPVAR_TRANSLATIONS_DIR`, or `os.Getwd()` if empty).
- `-locales`: Locale code to generate in `translations.yml` (repeatable; defaults to `APPVAR_TRANSLATIONS_LOCALES`).
- `-e`: File or path pattern to exclude (`filepath.Match` or exact relative path; repeatable).

Existing translations and comments in loaded `translations.yml` files are preserved when `./translations.yml` is regenerated. See [CLI](../cli.md) for running management commands.

### Built-in Finders and Custom Finder Hooks

`make-translations` runs three built-in `Finder` implementations plus any custom `Finder`s registered on `TranslationFinderHookName` (`"translations.finder.register"`):

```go
type Finder interface {
	Find(fSys fs.FS, isExcluded func(filename string) bool) ([]Translation, error)
}
```

1. **Template finder**: Walks files matching `APPVAR_TRANSLATIONS_EXTENSIONS` (`tmpl`, `html`, `txt` by default) and extracts string literals passed to `T`, `Translate`, and `P` inside `{{ ... }}` blocks.
2. **Go AST finder**: Parses `.go` files (skipping `*_test.go`) that import `github.com/Nigel2392/go-django/src/core/trans` (or aliases configured via `APPVAR_TRANSLATIONS_PACKAGES`) and extracts string literal calls to `S`, `T`, `P`, and `SP`.
3. **Model finder**: Walks all models registered on `django.Global.Apps`, emitting entries for each model name (`cType.Model()`) and every field label (`field.Label(context.Background())`) under synthetic paths `.models/<app>/<model>` and `.models/<app>/<model>/fields/<field>`.

## Plural Rules and Time Formats

When `make-translations` adds a new locale to the `translations.yml` header, it populates `nplural`, `rule`, `short_time_format`, and `long_time_format` from a built-in table covering over 65 locales (including `en`, `nl`, `fr`, `de`, `es`, `ar`, `uk`, `ja`, `zh`, and more), or defaults unknown locales to `nplural: 2` and `rule: '(n != 1) ? 1 : 0'`.

An example `translations.yml` header and plural entry:

```yaml
generator: "godjango"
created: "2023-10-01T12:00:00Z"
locales:
  nl:
    nplural: 2
    rule: '(n != 1) ? 1 : 0'
    long_time_format: '%A %-d %B %Y om %H:%M:%S'
    short_time_format: '%H:%M:%S %d-%m-%Y'

---

text: Document
plural: Documents
locales:
  nl:
    0: Document
    1: Documenten
```

On the server, plural rule expressions are evaluated using `govaluate` with parameter `n`; in `/i18n/translations.js`, the same rule string is evaluated directly as JavaScript.

## System Check

`TranslationsAppConfig.Check` verifies that at least one locale translation map was loaded. If `len(c.translations) == 0`, it emits a warning check:

- ID: `"translations.no_translations"`
- Message: `"Translations are not set up. Please run the make-translations command to find and add translations."`

See [Checks](../checks.md) for managing startup check messages.

## Notes and Caveats

- **`APPVAR_TRANSLATIONS_DIR` expects `[]string`**: Although the inline comment in `contrib/translations/settings.go` says `// string`, `make-translations` reads `APPVAR_TRANSLATIONS_DIR` as `[]string` (`django.ConfigGet(..., APPVAR_TRANSLATIONS_DIR, []string{})`). Always pass a `[]string` value.
- **`APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE` string key**: The constant value is `"APPVAR_TRANSLATION_ACCEPT_LANGUAGE"` (without an `S` on `TRANSLATION`). Always reference `translations.APPVAR_TRANSLATIONS_ACCEPT_LANGUAGE` rather than typing the string key manually.
- **`APPVAR_TRANSLATIONS_LOCALES` type difference**: `make-translations` reads `APPVAR_TRANSLATIONS_LOCALES` as `[]string`, whereas the `translations.Translate` helper reads `[]language.Tag`. Use `[]string` when invoking `make-translations`, or pass `locales...` explicitly to `translations.Translate`.
- **Repeatable CLI flags**: `make-translations` uses `flags.List` for `-dir`, `-locales`, and `-e`, so pass multiple values by repeating the flag (e.g. `-locales en -locales nl`) rather than comma-separating them.
- **Unmatched `"lang"` cookie formatting**: `TranslatorMiddleware` passes `lang.String()` (from `*http.Cookie`) into `language.MatchStrings`; if no `"lang"` cookie is set, `(*http.Cookie)(nil).String()` safely yields `""` and falls back to the `Accept-Language` header.
